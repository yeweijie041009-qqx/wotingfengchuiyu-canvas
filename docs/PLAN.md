# AI 短剧画布 · 本地方案（MiniMax-H3 / RTX 4060 Laptop）

> 基于对这台机器的实测审计。所有数字都是"实测/推算"，不是宣传值。

## 1. 现状审计（2026-11-01 实测）

| 项 | 实测值 | 判断 |
|---|---|---|
| GPU | RTX 4060 Laptop，**8188 MB VRAM**，驱动 616.92 / CUDA 13.4 | 能跑，但只能跑"低显存模式" |
| 内存 | **16176 MB（16 GB）** | **最大瓶颈**，比显存更要命 |
| ComfyUI | 0.42.5，torch 2.12.1+cu130，Python 3.13.12 | 正常 |
| 磁盘 | C 75.7G / D 183.6G / E 180.1G / F 105.9G 空闲 | 够用 |
| 模型目录 | `E:\Comfy-Desktop\ComfyUI-Installs\ComfyUI\ComfyUI\models`（`ComfyUI-Shared` 的 models 是空壳） | 注意别放错 |
| 已装模型 | H3 fl2va int8 19.5G / ref2va int8 31.7G / Qwen3-VL 32B 文本编码器 int8 25.3G / 视频VAE 4.85G / 音频VAE 0.56G / turbo LoRA 8步 1.82G / 4步 0.29G | **只有视频，没有图像模型** |
| 自定义节点 | `comfyui-h3-multishot`(2.6.5) / `ComfyUI-MiniMaxH3-Easy-Unified` / `ComfyUI-YCNodes-MiniMax-H3` / `comfyui-kjnodes` | 齐全，且 multishot 正好是"多镜头一镜到底" |
| 启动链路 | `standalone-env` 里**没有 torch**；真正能跑的是 `ComfyUI\ComfyUI\.venv\Scripts\python.exe`；且 `comfy_aimdo` 版本比 main.py 旧（`nvml_pressure` 参数不认） | 已用 `studio/tools/start_comfy.py` 兼容层绕过，不改动原安装 |

### 关键结论：16 GB 内存才是天花板

H3 fl2va 权重 19.5 GB、文本编码器 25.3 GB，**都大于 16 GB 内存**，也远大于 8 GB 显存。
结果是每次生成都要从 SSD 反复换入换出 ~45 GB 权重。显存不够只是慢，内存不够是"反复读盘"。
所以真实速度必须实测（`studio/bench.py`），不能拍脑袋。

**性价比最高的升级：内存 16G → 64G**（笔记本若能加，约几百元），收益远大于任何软件优化。
其次是整机换 24G 显存以上（4090/5090）——那才是"一天出十条短剧"的门槛。

## 2. "跟 LibTV 一模一样"的可行域

| LibTV 能力 | 本机能否复刻 | 说明 |
|---|---|---|
| 无限画布 + 节点连线 + 工作流复用 | ✅ 100% | 纯前端，与模型无关 |
| 剧本 / 分镜脚本 / 镜头语言 / Prompt 编译 | ✅ 100% | DeepSeek 强项；也可接本机 Ollama |
| 一键成片、批量分镜 | ✅ | 有 H3 就能文生视频+音频（t2va 自带音效/对白） |
| 多机位 / 多镜头一镜到底 | ✅ | `comfyui-h3-multishot` 天生为此设计 |
| 9/25 宫格分镜、四宫格推演 | ⚠️ 降级 | 需要图像模型；现在只能"先生成视频再抽帧" |
| 角色三视图 / 主体库（角色一致性） | ⚠️ 降级 | H3 的 ref2va 可做参考图一致性，但没有图像模型就出不了"三视图" |
| 局部重绘 / 扩图 / 抠图 / 打光 | ❌ 缺模型 | 需补 Flux/Qwen-Image/SDXL 之一（6–12 GB） |
| 内置剪辑、宫格切分、抽帧 | ✅ | ffmpeg/Pillow 即可，不必再调模型 |
| Agent 双入口（Skill 接口） | ✅ | 本方案原生提供 HTTP API，人和 Agent 共用 |

**一句话**：画布、编排、剧本、视频主线全部可行；图像类"专业功能"要么补一个图像模型，要么降级。

## 3. 架构

```
┌──────────── 浏览器（无限画布，无构建步骤）────────────┐
│ 文本/脚本/图片/视频/音频 五类节点 · 连线 DAG · 检查器 │
└───────────────┬──────────────────────────────────────┘
                │ HTTP(JSON)  ← 同一套 API 给 Agent 用
┌───────────────▼───────────────┐
│ studio/server.py  (stdlib)    │  任务队列(单卡串行) · 断点续跑 · 缓存
│  · /api/story  → DeepSeek     │  剧本→分镜→镜头 prompt 编译
│  · /api/render → ComfyUI      │  H3 图构建 → 提交 → 轮询 → 归档
│  · /api/project → 画布存档    │
└───────────────┬───────────────┘
                │ /prompt /history /view
┌───────────────▼───────────────┐
│ ComfyUI :8188 + MiniMax-H3    │  唯一的"渲染农场"
└───────────────────────────────┘
```

设计原则（针对这台机器）：
1. **串行队列**：一张卡，同时只跑一个任务，避免 OOM。
2. **一切可断点**：每个镜头是一个独立任务，失败只重跑该镜头。
3. **结果缓存**：同 prompt+seed+参数 → 直接复用，不重复烧机时。
4. **夜间批处理**：脚本一次排 6 个镜头，关机前点一次，早上收片。
5. **低分辨率草稿 → 定稿放大**：360P/480P 抽卡，选中再用 latent upscaler 提清晰度。

## 5.5 图像能力（M-A，已完成）

SDXL base 1.0（6.46 GiB，hf-mirror 下载，放在 `studio/models`，用 `extra_model_paths.yaml`
挂给 ComfyUI，原安装零改动）。

| 功能 | 实现 | 实测 |
|---|---|---|
| 单图 | 文生图 768×1344 / 28 步 | 27 秒 |
| 角色三视图 | 一次出 5 个角度、同一套服装 | 24 秒，一致性好 |
| 四宫格分镜 | **4 张独立出图再拼版**（不是让模型画格子） | 100 秒 |
| 九宫格分镜 | 9 张独立出图再拼版 | ~3.5 分钟 |

两个坑：
1. SDXL 的 CLIP **读不懂中文**，中文提示词会出随机图 → 已加 `translator`
   （config.json 有 api_key 就自动中译英，没有则提示写英文）。
2. 让 SDXL"画一张 2×2 格子图"不稳定（会画成 3×3，或干脆画成单张），
   所以改成多张独立出图 + PIL 拼版，稳定且每格分辨率更高。

局限：没有 IPAdapter/PuLID，跨图角色一致性只靠提示词，不保证同一张脸。

## 5. 实测结果（2026-11-01，本机真实跑通）

| 质量档 | 参数 | 单镜头 5 秒耗时 | 显存峰值 |
|---|---|---|---|
| 草稿 | 360P / 4 步 / 4-step LoRA | **97 秒** | ~5.6 GB |
| 标准 | 480P / 8 步 / 8-step LoRA | **324 秒（5 分 24 秒）** | **7.4 / 8.2 GB（很紧）** |
| 精细 | 720P / 8 步 | 未测 | 有爆显存风险 |

参考：2 秒镜头 360P/4 步 = 69 秒。480P/8 步的采样是 31.6 秒/步 × 8 步。

**折算产能**
- 草稿档：30 秒短剧（6 镜）≈ 10 分钟一遍
- 标准档：6 镜 ≈ 27 分钟；按 2 倍抽卡 ≈ 1 小时一条
- 推荐工作流：**草稿档批量抽卡选镜头 → 只把选中的镜头用标准档重跑 → 拼接**

其他实测：单镜头原始 mp4 时间戳严格 24fps（41.7ms/帧），播放平滑；
成片必须按 CFR 重编码拼接，直接 remux 会导致播放卡顿（已修）。
